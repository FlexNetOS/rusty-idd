# integrate-fleet-handoff - Design

## Context

Integration work item `work:integrate-fleet-handoff` maps capability `capability:fleet-handoff` in layer `layer:coordination-communication` to owner repos and validation gates generated by Rusty IDD.

## Goals / Non-Goals

**Goals:**

- Adopt the current owner/upstream surfaces before cutting local behavior.
- Keep Rusty IDD glue thin: DTO mapping, deterministic output, feature flags, validation, and CLI/API calls.
- Preserve `crates/core` as std-only.

**Non-Goals:**

- Starting host services, daemons, MCP servers, or vault relays from default Rusty IDD workflows.
- Downgrading a working upstream or owner-repo capability to simplify implementation.

## Decisions

- Implementation boundary: add `rusty-idd knowledge integration-owners` as a read-only graph join from one integration work item to its owner repos.
- The report consumes `.idd/knowledge/integration-plan.json` and `.idd/knowledge/system-architecture.json`; it does not rescan or mutate peer repos.
- Every owner surface records branch, dirty state, markers, roles, local architecture summary when available, evidence paths, and native diagnostic command candidates.
- Every consolidation cut after this report must cite failing build, audit, platform, or scope evidence and include rollback.

## Risks / Trade-offs

- Cross-repo ownership may require separate PRs in owner repos; this Rusty IDD change records the execution contract first.
- Native diagnostics may fail for upstream reasons; failures are evidence, not permission to pre-filter.

## Migration Plan

1. Generate owner-surface JSON and Markdown for `integrate-fleet-handoff`.
2. Use the report to identify owner repo evidence paths and native diagnostics before any peer-repo consolidation.
3. Apply the thinnest Rusty IDD boundary and focused tests.
4. Refresh `.idd/knowledge/*` and `.idd/MANIFEST.tsv`.
5. Run full Rusty IDD gates and owner-repo smoke tests.
