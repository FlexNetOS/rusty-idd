# integrate-prompt-front-door - Design

## Context

Integration work item `work:integrate-prompt-front-door` maps capability `capability:prompt-front-door` in layer `layer:front-door-experience` to owner repos and validation gates generated by Rusty IDD.

## Goals / Non-Goals

**Goals:**

- Adopt the current owner/upstream surfaces before cutting local behavior.
- Keep Rusty IDD glue thin: DTO mapping, deterministic output, feature flags, validation, and CLI/API calls.
- Preserve `crates/core` as std-only.

**Non-Goals:**

- Starting host services, daemons, MCP servers, or vault relays from default Rusty IDD workflows.
- Downgrading a working upstream or owner-repo capability to simplify implementation.

## Decisions

- Implementation boundary: Adopt upstream repo surface first, run native diagnostics, then add thin Rusty IDD mapping.
- Every consolidation cut must cite failing build, audit, platform, or scope evidence and include rollback.
- Treat prompt/front-door inputs as producers for the full Rusty IDD OpenSpec
  lifecycle: plans, ADRs, specs, tasks, implementation, validation, and audit
  records.
- Respect the parent-managed automation environment: RTK wraps command
  execution, ICM/VOX/GRIT are rtk-ai foundation surfaces, Yazelix carries the
  current tree-sitter/terminal/runtime direction, and Beads is mandatory for
  future contributor workflows through Yazelix.
- Adopt-first inputs:
  - `github.com/f/prompts.chat`
  - `github.com/f/ai-prompt`

## Risks / Trade-offs

- Cross-repo ownership may require separate PRs in owner repos; this Rusty IDD change records the execution contract first.
- Native diagnostics may fail for upstream reasons; failures are evidence, not permission to pre-filter.
- This slice records Beads/Yazelix/RTK expectations but does not select a
  canonical Beads implementation or start host services.

## Migration Plan

1. Re-read current owner repo docs, scripts, CI, and generated architecture artifacts.
2. Adopt the relevant current surfaces as-is or reference pinned upstream mirrors.
3. Run native diagnostics before cuts.
4. Apply the thinnest Rusty IDD boundary and focused tests.
5. Refresh `.idd/knowledge/*` and `.idd/MANIFEST.tsv`.
6. Run full Rusty IDD gates and owner-repo smoke tests.
