# Architecture Graph Workflow Upgrade

Date: 2026-06-21
Branch: `integration/system-architecture-graph-workflow`
OpenSpec change: `openspec/changes/upgrade-architecture-graph-workflow`

## Purpose

This note records the first Rusty IDD workflow upgrade that treats the
CodeGraph and repomix integrations as architecture-mapping capability rather
than only code search or context packing helpers.

Rusty IDD remains the lifecycle control plane. CodeGraph supplies structural
source graph evidence. repomix supplies bounded context package and token-policy
evidence. The new artifact maps both into the automated order used for intake,
architecture mapping, specification, implementation, validation, and handoff.

## Implementation

- Added architecture graph DTOs in `crates/knowledge`.
- Added `rusty-idd knowledge architecture --workspace <path> --out <file>`.
- Extended `rusty-idd knowledge refresh` to write:
  - `.idd/knowledge/architecture.json`
  - `.idd/knowledge/architecture.md`
- The architecture graph records:
  - CodeGraph-backed file, node, edge, language, hotspot, and parse-failure
    counts.
  - repomix-backed packed file, token, top-file, suspicious-file, and skipped
    file counts.
  - repo components grouped by crate/control-plane surface.
  - integration surfaces for `codegraph-rust`, `repomix-rs`, OpenSpec, and
    audit/manifest evidence.
  - Rusty IDD automation stages and edges from stage to surface.

## Token Policy Cut

The first real-workspace architecture smoke exceeded the default 120,000 token
budget because the repomix side included external mirrors and archived TUI
OpenSpec material. The retained cut excludes `third_party/upstream/**`,
`crates/external/**`, and `crates/tui/openspec/changes/archive/**` from the
architecture pack.

This is not a feature downgrade: CodeGraph remains the structural source of
truth for graph data, while repomix supplies bounded context package metrics for
the active workflow.

## Freshness Gate Upgrade

`just knowledge-check` now regenerates and compares:

- `.idd/knowledge/index.json`
- `.idd/knowledge/report.md`
- `.idd/knowledge/architecture.json`
- `.idd/knowledge/architecture.md`

This ensures the architecture graph participates in the same automated
freshness checks as the existing knowledge artifacts.

## Freshness Loop Fix

`AI_MERGE/validation_report.md` is generated by `rusty-idd validate`. Including
that generated report in repomix-backed report or architecture pack metrics made
the workflow order-sensitive: validation could change token counts after
knowledge refresh.

The retained fix excludes `AI_MERGE/validation_report.md` from report and
architecture pack metrics. The validation report remains tracked and included in
the manifest; it is only excluded from token-package metrics to avoid a
self-invalidating generated-artifact loop.
